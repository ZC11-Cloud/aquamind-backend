## 2. 验收阈值

- 功能通过率 >= 95%
- 平均响应时间 <= 2.5 s
- P95 响应时间 <= 4.5 s
- 稳定性错误率 <= 1%
- 崩溃次数 = 0

说明：问答接口采用流式输出，当前统计的接口耗时为流式响应全部结束后的总完成时间，而非首字返回时间。因此，时延指标主要用于比较优化前后和不同并发条件下的链路完成效率，不宜完全按照普通同步接口阈值作刚性判定。

### 4.1 性能结论

重测后系统并发稳定性明显改善，30 并发和 50 并发场景均未出现失败请求，说明中高并发下的大面积报错问题已基本消除。考虑到问答接口为流式输出，当前平均响应时间和 P95 响应时间更应理解为完整回答链路耗时；从这一角度看，系统总完成时长仍有进一步优化空间，但其流式交互可用性不能仅由该指标单独否定。

### 4.2 主要瓶颈

- RAG 问答接口耗时最高，是整体时延的主要来源。
- 吞吐率随并发增加而上升，但增幅逐步变缓，说明单机部署能力接近上限。
- 10 并发场景仍出现 1 次 500 错误，表明系统尚存在偶发异常。

## 5. 总体结论

1. 优化后的系统在并发稳定性方面已有明显提升。
2. 功能测试仍未完全通过验收，会话删除与空输入校验是当前主要问题。
3. 系统适合毕业设计原型验证与小规模演示，但尚未达到低时延、高稳定的生产级要求。
4. 后续应重点优化删除接口逻辑、边界输入校验以及 RAG 问答链路的完整生成时长。
